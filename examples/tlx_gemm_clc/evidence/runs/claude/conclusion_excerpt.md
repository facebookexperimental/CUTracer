## F1 (higher rank): CLC response, generic read then async write, no `fence.proxy.async`

| Field | Content |
|---|---|
| Buffer | CLC response, 16 B at smem `global_smem+131296` (trace address `0x204e0`; `0x200e0` in SASS operands). One stage (`NUM_CLC_STAGES=1`), reused for every tile a CTA steals. |
| Edge | **First access:** generic read `ld.shared.b128` (SASS `LDS.128 R4,[UR+0x200e0]`) in all three consumer roles: epilogue at PC `0x1b40`, MMA warp at `0x2b90`, TMA-load warp at `0x3730`. Each role then releases `clc_empty` (`mbarrier.arrive`, SASS `SYNCS.ARRIVE.TRANS64.A1T0 [..+0x20100]` at `0x1bc0`, `0x2c20`, `0x37c0`). **Second access:** the producer (epilogue, lane 0 of warp 0) waits `clc_empty` (`0x830`) and issues `clusterlaunchcontrol.try_cancel` (`UGETNEXTWORKID.BROADCAST` at `0x920`). That is an async-proxy write to the same 16 B. Direction: generic read, then async write (WAR across proxies). |
| Missing mechanism | Each reading thread needs `fence.proxy.async.shared::cta` after its read and before the release. PTX ISA 8.6 says "A proxy fence is required to synchronize memory operations across different proxies". 9.7.15.18 says try_cancel writes the response with "weak async-proxy writes". **Inferred** from the cited rules. |
| Code facts | No `fence.proxy` between the read and the arrive in any role: PTX lines 1038 to 1051, 1221 to 1235, 1620 to 1634, and the SASS in `out/artifacts/sass_excerpts.txt` (**observed**). Source: `triton/language/extra/tlx/dynamic_launch.py`, `clc_consumer`, between `_clc_query` and `barrier_arrive` (**observed**). |
| Trace, before | `out/trace_base/edges.txt`: rows `0x1b40/0x2b90/0x3730 -> 0x920` have 648 occurrences and `fence_seen=0` (**observed**). The trace confirms both accesses hit the same bytes, `0x204e0` (`out/trace_base/excerpt_cta2_clc.ndjson`, **observed**). |
| Classification | **Violation.** The release chain exists (`clc_empty` init count 3, one arrive per role, producer waits), but that orders execution only. The arrive is predicated on the loaded tile id, which is a data dependence. The PTX model does not accept a data dependence as cross-proxy ordering. |
| ISA evidence | PTX variant A adds 3 × (`MEMBAR.ALL.CTA; FENCE.VIEW.ASYNC.S`), each between a CLC `LDS.128` and its arrive (`out/fix/fix_A.sass`, opcode delta in timeline step 4). So the shipped binary lacks the fence (**causal**: the input change produced exactly these instructions). |
| Trace, after | AB build, `out/trace_fix/edges.txt`. Epilogue: `fence_seen=324`, `fence_and_link=324`. MMA warp: `fence_seen=108/108`. TMA warp: `fence_seen=108/108`. No other edge changed category (**observed**). The epilogue's other 108 rows are same-warp rows, which the script does not fence-check. The fence there runs with full mask before `BAR.SYNC` (SASS `0x1b90`/`0x1ba0`, **observed**). The MMA and TMA rows stay `sync_lanes_unresolved` because ptxas emits no `WARPSYNC` for the PTX `bar.warp.sync -1` before the lane-0 arrive. At the PTX level that `bar.warp.sync` joins the lanes (PTX 9.7.15.2, **inferred**). |
| Runtime consequence | None observed. Here is what could happen if the try_cancel write landed before a role's read: that role would decode the next tile id. The three roles would then disagree on the tile sequence, giving a skipped or duplicated tile (wrong or uninitialised `C`, which comes from `torch.empty`) or a hang (**inferred**). In this binary the arrive waits on the `LDS` value, so on this GPU the read returns before the release (**inferred** from SASS). That explains why no failure is seen. A different compiler or GPU is not bound by this. |

**Proposed fix (source):** `out/fix/dynamic_launch_fence.patch`. It adds `fence("async_shared")` to `tlx.clc_consumer` after `_clc_query` and before `barrier_arrive`, which fixes every TLX kernel that uses the CLC pipeline. Verified: PTX gains exactly 3 `fence.proxy.async.shared::cta`. SASS gains the same 3 MEMBAR+FENCE pairs between `LDS.128` and the arrive (`out/fix/srcfix.sass`). Repro passes 0/50. I restored the original file afterwards (`sha256sum -c` OK, timeline step 7).
